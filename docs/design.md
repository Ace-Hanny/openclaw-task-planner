## 二.1、月计划生成模式

### 月计划文档结构

```markdown
# YYYY年M月计划（优化版）

> 📅 来源：年度目标
> 🎯 本月定位：Qx进度说明

## 年度TOP3目标对照
| 年度目标 | 本月进度要求 | 本月状态 |

## 核心目标
| 目标 | 本月关键结果 | 关联年度目标 |

## 阶段性任务（来自工作室计划）
| 任务 | 年度目标 | 本月目标 | 第1周 | 第2周 | 第3周 | 第4周 |

## 周期任务
### 📝 内容输出（认知资产层）
### 📚 学习成长（能量来源层）
### 💪 健康管理（身体基础层）

## 阅读计划

## 健康监测指标

## 月度复盘要点
```

### 生成逻辑

1. **读取年度目标文档** — 获取TOP3目标、阶段性任务、周期任务
2. **确定本月定位** — 根据季度进度确定本月重点
3. **拆解阶段性任务** — 按周拆分进度要求
4. **整理周期任务** — 分类并标注建议时间
5. **生成文档** — 写入知识库

## 二.2、阶段性任务管理规则

### 定义

**阶段性任务**：持续时间超过1个月的任务，需要跨月执行。

### 记录位置

| 记录位置 | 作用 | 更新方式 |
|---------|------|---------|
| **年度目标文档** | 任务清单、整体进度 | 新增时添加，完成时标记 |
| **月度计划文档** | 本月具体目标 | 每月继承未完成的任务 |

### 操作流程

**新增阶段性任务时：**
1. 在年度目标文档（工作室计划部分）的"接下来任务"中新增
2. 在当前月份的月度计划中列出，写明本月目标

**每月更新时：**
1. 月度计划继承上月未完成的阶段性任务
2. 写明本月要达成的具体目标

**任务完成时：**
1. 在年度目标文档中标记"✅ 已完成"
2. 在月度计划中标记完成状态

### 示例

**年度目标文档：**
```plaintext
接下来任务：
1. AI智能体实战营资料准备
2. 小红书货架研究
3. 夜校资料准备
4. 【新增】AI工作坊课程开发（预计3-4月）
```

**3月计划：**
```plaintext
阶段性任务：
- AI智能体实战营资料准备 → 本月目标：完成大纲
- 小红书货架研究 → 本月目标：完成调研
- 夜校资料准备 → 本月目标：确定课程框架
- AI工作坊课程开发 → 本月目标：完成课程框架
```

**4月计划：**
```plaintext
阶段性任务：
- AI工作坊课程开发 → 本月目标：完成课件制作
```

## 四、日计划生成流程

**阶段一：日计划初稿（信息确认）**
- 时间：每日 8:00 推送
- 目的：汇总待办 + 建议时间安排
- 内容：今日行程 + 近期任务 + 今日待办 + 建议安排

**阶段二：正式日计划（执行依据）**
- 触发：用户确认后
- 目的：写入表格，开始执行
- 内容：用户确认后的任务列表

### 确认流程

```plaintext
8:00 推送日计划初稿
    ↓
用户查看、调整
    ↓
用户回复"确认"
    ↓
写入日计划表格（正式执行）
```

### 调整规则

**用户说 → 我翻译 → 确认后执行**

| 用户说 | 我理解 | 确认话术 |
|-------|-------|---------|
| "把XX挪到后天" | 更新飞书任务截止日期为后天 | "要把XX任务的截止日期改成后天吗？" |
| "今天不做XX" | 从今天移除，保留在任务池 | "把XX从今天移除，后续还会提醒，可以吗？" |
| "删掉XX" | 彻底删除任务 | "要彻底删除XX任务吗？删除后无法恢复。" |
| "XX以后再说" | 标记为暂停，暂停提醒 | "把XX标记为暂停，暂时不再提醒？" |

### 操作类型映射

| 操作 | 飞书任务 | 周计划表格 | 后续提醒 |
|-----|---------|-----------|---------|
| 挪到某天 | 改截止日期 | 不变 | 新日期提醒 |
| 今天不做 | 不变 | 不变 | 继续提醒 |
| 暂停任务 | 改状态为暂停 | 标记暂停 | 暂停提醒 |
| 彻底删除 | 删除任务 | 标记取消 | 不再提醒 |

### 存储位置

- **日计划初稿**：`memory/YYYY-MM-DD.md`
- **确认状态**：`memory/YYYY-MM-DD.md`
- **正式日计划**：多维表格 `tblziYVnaXv0BUNn`

### 输入数据（共5个来源）

| 序号 | 来源 | 数据位置 | 提取逻辑 |
|-----|------|---------|---------|
| 1 | 昨日计划 | `memory/YYYY-MM-DD.md` → 「明日待办」 | 全部提取 |
| 2 | 周计划 | 飞书文档「第XX周计划」→ 「每日任务 → 当天」 | 提取当天任务 |
| 3 | 飞书任务 | 飞书任务系统 | 取本周内截止 + 高优先级任务 |
| 4 | 飞书日历 | 飞书日历系统 | 取今日行程（标记为「不可变」） |
| 5 | 番茄时钟 | 飞书多维表格「日计划表」 | 取昨日「状态 ≠ 已完成」的任务 |

```plaintext
昨日计划 ────┐
周计划 ──────┤
飞书任务 ────┼──→ 合并 → 去重 → 排序 → 今日待办
飞书日历 ────┤
番茄时钟 ────┘
```

### 生成逻辑

1. **读取周计划**：获取本周目标和任务列表
2. **读取当日行程**：飞书日历中的会议、约见（不可变的时间块）
3. **读取飞书任务**：获取待办事项
4. **读取前一天 memory**：提取昨日的「明日待办」
5. **读取番茄时钟**：获取昨日未完成任务
6. **AI 整合**：
   - 行程时间块标记为「不可变」
   - 周计划每日任务优先安排
   - 周期任务按建议时间填充
   - 飞书任务按优先级补充
   - 昨日未完成任务延续
7. **推送**：发送到飞书私聊，等待用户确认

## 番茄时钟数据同步方案

### 问题背景

番茄时钟应用使用飞书应用身份（tenant_access_token）调用 API，但应用身份没有多维表格写入权限（返回 `Forbidden` 错误）。而 OpenClaw 工具使用用户身份（user_access_token），可以正常写入。

### 解决方案：操作记录 + 自动同步

#### 架构设计

```plaintext
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   番茄钟前端     │────▶│   番茄钟后端     │────▶│   OpenClaw      │
│  (用户操作)      │     │  (操作队列)      │     │  (用户身份)      │
└─────────────────┘     └─────────────────┘     └─────────────────┘
                               │                        │
                               │                        ▼
                               │                 ┌─────────────────┐
                               └────────────────▶│   飞书多维表格   │
                                                 └─────────────────┘
```

#### 同步流程

1. 用户在番茄钟点击「完成任务」
2. 前端调用 `/api/pending-operations` 记录操作
3. 前端立即更新本地状态（用户无感知）
4. OpenClaw heartbeat（每 30 分钟）检查待同步操作
5. 使用 `feishu_bitable_app_table_record` 工具同步到飞书
6. 同步成功后删除操作记录

#### 配置信息

| 配置项 | 值 |

## 十、日计划系统优化记录（2026-03-26）

### 1. 延续任务处理优化

**问题：** 延续任务（昨日未完成）自动出现在番茄钟里，未经过用户确认。

**改进方案：** 延续任务纳入日计划确认流程。

**新的输入数据来源：**

| 序号 | 来源 | 数据位置 | 提取逻辑 |
|-----|------|---------|---------|
| 1 | 昨日计划 | `memory/YYYY-MM-DD.md` → 「明日待办」 | 全部提取 |
| 2 | 周计划 | 飞书文档「第XX周计划」→ 「每日任务 → 当天」 | 提取当天任务 |
| 3 | 飞书任务 | 飞书任务系统 | 取本周内截止 + 高优先级任务 |
| 4 | 飞书日历 | 飞书日历系统 | 取今日行程（标记为「不可变」） |
| 5 | 延续任务 | 飞书多维表格「日计划表」 | 取计划日期 < 今天 且 状态 = 待执行的任务 |

**延续任务处理规则：**
- 延续任务纳入日计划待办列表，标记为「延续」
- 用户确认时可以选择：**保留 / 推迟 / 删除**
- 只有确认「保留」的任务才写入日计划表（番茄钟读取）

### 2. 番茄钟任务排序优化

**问题：** 番茄钟任务列表未按时间顺序排列。

**改进方案：** 按时间块开始时间排序。

**排序规则：**
- 提取时间块中的开始时间（格式：HH:MM）
- 中文时段映射：早→07:00，上午→09:00，中午→12:00，下午→14:00，晚→19:00
- 按时间升序排列

### 3. 任务状态同步优化

**问题：** 月度任务表中的任务状态未及时更新。

**改进方案：** 任务完成时同步更新多个数据源。

**同步逻辑：**
- 飞书任务完成 → 更新飞书任务状态
- 日计划表完成 → 更新日计划表状态
- 月度任务表完成 → 更新月度任务表进度和状态
